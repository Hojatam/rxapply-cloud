1 · TL;DR

Where the project stands and what each phase adds

Today (end of Phase E). The full 21-agent stack runs locally on Cowork. The admin dashboard controls everything from one screen. n8n cron triggers are configured but inactive (toggle on after sanity-checking). Every agent journals to agent_journal; every intel agent funnels through paya.py for schema validation. Quality is structural-only — 12/12 test scenarios pass, no real audience yet.

The big architectural finding from Phase C. All 10 added agents shipped as no-LLM Python. Deterministic, fast, idempotent where it matters, $0 incremental cost. The trade-off: prose-quality outputs (Payvand outreach emails, Kherad quality scores, Mehmandar nudges) are template-shaped today. Some need an LLM pass before going live; some don't.

What this plan delivers.

  • Phase F — quality + robustness while staying local. Selective LLM upgrades, idempotency, backups, real auth on the dashboard.
  • Phase G — replace one intel source with real data; wire one inbound channel to a real sandbox account; document the local→cloud migration.
  • Phase H — close the pre-prod gates: hard send-real-emails approval, Stripe-test webhook to customers, Cal.com test webhook to consultations.
  • Phase I — first paid commitments. Promote one dry-run channel (recommend Telegram). Resend for nurture. Plausible. Stripe live. DataForSEO. Total: ~$50/mo to start.

★ Phase J · post-V2.5

M1 launch · the customer-facing half

After V2.5 the internal stack is complete. What's missing is everything a customer touches: a public site, the Destination Advisor quiz, real social posting, real payment + booking. Sequenced for fastest path to first paying customer (M3 in plan-v3 = UK Guide launch).

J1 · Public site shell

Next.js site, 3 locales (en/fa/ar), RTL aware

~3 days
$0 in dev, ~$0 hosted (Vercel free tier)

A new rxapply-web/ sibling folder with Next.js App Router. Three routes only at MVP: / (homepage), /advisor (the quiz), /blog (Sepehr articles when they land). next-intl for routing locales; Vazirmatn font for fa/ar; dir="rtl" wired automatically on locale switch.

Why now: blocker for everything customer-facing in plan-v3. Without it, no email signups can happen, no quiz can run, no posts can deep-link.

J2 · Destination Advisor quiz UI

Wire Rahnama's scoring to a public 15-question form

~1 day
existing Rahnama agent · adds POST /advisor/score route

15-question form per plan-v3 §02. Submission posts to a new proxy route POST /advisor/score which spawns Rahnama with the answers, gets back the top-3 destinations + per-dimension scoring, persists a leads row (email-gated). The agent already exists; this is the missing UI half.

Why now: primary lead magnet. Plan-v3 §1 calls for "Advisor completions/mo: 50 → 2,500" as a Year-1 KPI. Today it's 0 because there's no UI.

J3 · 3,000-list reactivation

One-time bilingual EN+FA campaign · MailerLite or Resend

~2 days incl. content
$10/mo MailerLite + content time

The 3,000 dormant Iranian-dentist contacts the founder already has. Use Compose to draft the reactivation message; Goyesh has FA-native voice. Drop into MailerLite or Resend, segment by language, send at off-hours Tehran time. Lowest-cost real audience signal you'll ever get.

Output: first real engagement_events rows. Bineh starts scoring real leads. Roya's heatmap stops being synthetic.

J4 · Promote ONE channel from dry-run to live

Telegram first (Bot API is the easiest social to integrate)

~0.5 day
$0 — Telegram Bot API is free

Schema is already forecast-ready (posted_url, posting_provider, posted_at columns added in V2.5). Replace the cross-post DRY_RUN step's "log" with a real sendMessage call to the Telegram Bot API. One file change in agents/cross-post/dryrun.py. Caption + image URL → posted to your channel.

Why Telegram first: simplest auth (bot token), no Meta App Review queue, ~50% of plan-v3's FA audience is on Telegram, low downside if it goes wrong (no algorithmic distribution to worry about).

J5 · Stripe-test + Cal.com webhooks

Edge functions populating customers + consultations

~1 day each
test mode = $0 · production keys later

Two Supabase Edge Functions. /functions/stripe-webhook with signature verification → upserts customers on first paid event, fires Resend confirmation. /functions/cal-webhook on Cal.com booking → inserts consultations, syncs to Mehmandar's pipeline.

Pre-req for J6: can't take payment without J5.

J6 · UK Guide launch (M3 in plan-v3)

First paid product · break-even month

~2 weeks of content + setup
$79 launch price · ~10 sales goal in first month

The first L3 product in plan-v3. Sepehr writes the master article (deep mode now exists in Pipelines), Goyesh translates to FA, Avang fans out across all platforms. Thinkific course holds the actual content, Stripe takes the payment, Resend confirms enrollment. Compose handles the launch IG post in 3 languages.

Why this matters: M3 in plan-v3 is the break-even month. Every internal feature we've built is in service of this moment. After J6, the rest is iteration.

Sequencing. J1 + J2 unblock everything. J3 in parallel (it's content work, doesn't depend on J1/J2 being live). J4 small enough to slip in any week. J5 is a 2-day sprint when you're a week from J6. J6 is the goal.

Phases F–I above are partially superseded: F is shipped (V2). G's "real intel sources" still relevant — but lower priority than J1–J3 for revenue. H's gates and I's social platforms map onto J5 + J4. Read F–I for the historical thinking, but plan from Phase J.
